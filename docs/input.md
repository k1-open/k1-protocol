# K1 Input API

状态：保留能力，当前 BLE GATT v1.11 尚未定义独立输入事件帧。

## 1. 当前实现

- 硬件包含触摸唤醒能力。
- BLE 语音输入通过 `VOICE_CMD (0x01)` 上报语音指令 ID、置信度和时间戳。
- `CONTROL_CMD (0x12)` 是 APP -> 设备控制命令，不是设备输入事件。
- 当前没有稳定的按键、触摸、滑动或手势 BLE 事件消息。

客户端不得把未定义帧类型或 `CONTROL_CMD` 当作输入事件使用。

## 2. 能力声明

在 Input API 正式发布前：

- 能力位中的 Input API 应报告为不支持。
- 设备发现输入能力未启用时，APP 不应显示依赖输入事件的交互。
- `VOICE_CMD` 仍可独立使用。

## 3. 后续建议格式

以下仅为设计建议，不是当前稳定协议：

| 字段 | 长度 | 说明 |
|---|---:|---|
| event_type | 1 | 按键、触摸、滑动、手势 |
| event_id | 1 | 事件编号 |
| value | 1 | 方向、计数或状态 |
| timestamp_ms | 4 | 设备时间戳，LE u32 |

新增帧类型应使用未占用的 `0x50-0x5F` 区间，并在发布前补充：

- 事件去抖和重复上报规则
- 触摸坐标是否公开
- 手势识别在设备端还是 APP 端完成
- 低功耗唤醒和连接状态处理
- 测试向量和互操作记录
