# K1 Display API

状态：草案  
协议版本：待设备联调后分配  
实现边界：Display API 对外开放，显示驱动和面板初始化实现保持私有。

## 1. 目标

Display API 为手机应用、配件和诊断工具提供稳定的显示控制能力，屏蔽底层显示驱动、面板时序和校准实现。

公开能力包括：

- 查询显示能力
- 初始化显示会话
- 刷新文本和图像
- 设置亮度
- 进入和退出睡眠
- 查询显示状态
- 清除显示内容

## 2. 能力查询

客户端连接后应先查询显示能力，至少获得：

- 最大宽度和高度
- 支持的颜色格式
- 最大单次图像大小
- 是否支持文本分页
- 是否支持局部刷新
- 亮度范围和步进
- 是否支持睡眠
- 当前固件和协议版本

客户端不得根据设备型号硬编码显示参数。

## 3. 逻辑接口

### 3.1 初始化显示

输入：

- 请求 ID
- 客户端协议版本
- 期望的显示模式

输出：

- 初始化结果
- 当前显示状态
- 有效显示尺寸
- 能力摘要

初始化必须幂等。重复初始化不得导致设备重启或显示异常。

### 3.2 刷新内容

输入：

- 请求 ID
- 内容类型：文本、图标、位图或分页内容
- 坐标
- 宽高
- 颜色格式
- 数据长度
- 分片序号
- 内容数据

输出：

- 刷新状态
- 已接收字节数
- 失败原因

大图像必须分片传输。客户端必须等待设备确认后再发送下一片。

### 3.3 设置亮度

输入：

- 请求 ID
- 目标亮度
- 可选渐变时长

输出：

- 实际生效亮度
- 是否被设备限制

亮度范围由能力查询返回。设备可以限制最低或最高亮度，但必须返回实际生效值。

### 3.4 睡眠和唤醒

支持：

- 进入睡眠
- 退出睡眠
- 查询当前状态

设备进入睡眠前应完成当前写入，不能留下半帧内容。

### 3.5 清除显示

清除全部内容或指定区域。清除操作必须在响应中返回完成状态。

### 3.6 查询状态

返回：

- 当前显示状态
- 当前亮度
- 当前内容版本
- 最近一次刷新结果
- 温度或限流状态（如支持）

## 4. 状态机

建议状态：

```text
UNINITIALIZED
INITIALIZING
READY
UPDATING
SLEEPING
ERROR
```

状态转换必须在协议文档中固定。无效状态下收到请求时，设备必须返回状态错误。

## 5. 错误处理

至少区分：

- 不支持的能力
- 非法坐标或尺寸
- 数据过大
- 分片顺序错误
- 校验失败
- 显示忙
- 温度限制
- 低电量
- 驱动内部错误

错误码必须稳定，不能依赖错误文本判断。

## 6. 性能和限制

正式协议必须定义：

- 单次刷新最大数据量
- 分片大小
- 刷新超时
- 最大重试次数
- 最大并发显示请求
- 局部刷新最小区域
- 图像格式和压缩方式

## 7. 不公开内容

- 面板初始化命令序列
- 显示控制器寄存器配置
- Gamma、亮度、色温和均匀性校准
- 显示私有算法
- 显示驱动源码和内部日志格式
- 生产显示测试参数
