# K1 Audio Protocol

状态：基于 K1 GATT v1.11 的公开草案  
适用范围：APP 订阅 K1 麦克风音频流

## 1. 特征

| UUID | 属性 | 方向 | 用途 |
|---|---|---|---|
| 4D530007-0000-1000-8000-00805F9B34FB | Notify | FW -> APP | 麦克风音频流 |

APP 必须先向该特征的 CCCD 写入 0x0001 开启订阅，取消订阅时写入 0x0000。

## 2. 发流策略

- 只有 APP 订阅 AUDIO_DATA 时，K1 才发送音频流。
- 连接建立后默认不发送音频流。
- 取消订阅后，设备应在 20 ms 内停止发流。
- 音频数据使用通用帧格式，FrameType = 0x40。

## 3. AUDIO_DATA 帧

Payload 长度：162 bytes，整帧长度：167 bytes。

| 偏移 | 长度 | 字段 | 说明 |
|---:|---:|---|---|
| 0 | 2 | seq | 帧序号，0-65535 循环，LE u16 |
| 2 | 160 | pcm | 8-bit signed PCM，20 ms @ 8 kHz |

音频参数：

| 参数 | 值 |
|---|---|
| 采样率 | 8 kHz |
| 声道 | 单声道 |
| 采样格式 | 16-bit 采集后取高字节，转换为 8-bit signed PCM |
| 静音值 | 0x00 |
| 帧间隔 | 20 ms |
| 帧率 | 50 帧/秒 |
| 数据率 | 约 67 kbps |
| 丢帧策略 | 允许丢帧，APP 使用 seq 检测 |

Android AudioTrack 的 ENCODING_PCM_8BIT 使用无符号格式，静音值为 0x80。APP 播放前应对每个字节执行异或 0x80 转换。

## 4. 连接参数

音频播放期间，APP 可以请求高优先级连接：

- 连接间隔约 15 ms
- 外设请求范围 15-30 ms
- 最终连接参数由手机 Central 决定

停止播放后应恢复 30-50 ms 的平衡模式以降低功耗。

## 5. 订阅顺序

1. 连接设备。
2. 发现服务。
3. 订阅 CMD_NOTIFY 的 CCCD。
4. 等第一次描述符写入完成。
5. 再订阅 AUDIO_DATA 的 CCCD。
6. 收到通知后开始音频播放。

部分 Android 设备会丢弃连续发送的第二次 CCCD 写入，因此不得并行写入两个订阅。

## 6. 丢帧和错误处理

- seq 不连续时，APP 应记录丢帧并根据播放缓冲补静音。
- 长时间丢帧时，APP 应重新协商连接参数或重新订阅。
- 设备不得发送超出协商 MTU 的音频帧。
- 收到取消订阅后，设备必须停止产生和发送音频数据。
- 音频流不可用时，设备保持其他服务和通知正常工作。

## 7. 隐私要求

- 音频流只能在用户明确开始相关功能后发送。
- APP 必须提供停止录音和取消订阅的入口。
- 日志不得保存原始音频数据。
- 公开示例不得包含真实录音或用户语音。
