# K1 Protocol Versions and Compatibility

本文定义 K1 协议版本发现、能力协商和兼容性要求。具体消息编号、UUID 和字节布局在设备联调完成后补充。

## 1. 版本格式

K1 协议使用：

```text
MAJOR.MINOR.PATCH
```

- MAJOR：不兼容的消息格式、状态机或安全要求变更
- MINOR：向后兼容的新增能力、字段或消息
- PATCH：错误码补充、文本修正和非行为性修改

## 2. 连接后的版本交换

手机与 K1 建立连接后，应读取：

- 协议主版本
- 协议次版本
- 协议修订版本
- 设备硬件版本
- 固件版本
- 支持的能力位
- 最大消息长度
- OTA 支持状态

缺少必需能力时，客户端必须停止对应功能，并向用户返回明确原因。

## 3. 兼容规则

1. 客户端和高版本设备通信时，可以忽略未知的可选字段。
2. 设备收到未知的必需能力请求时，必须返回不支持错误。
3. 同一主版本内新增字段必须保持默认值兼容。
4. 主版本变化时，必须提供迁移说明。
5. 删除字段或改变字段含义必须提升主版本。
6. 不允许通过修改现有字段含义实现新功能。

## 4. 能力位

能力位用于声明可选能力，不替代版本号。应用不能仅根据固件版本推断能力，必须读取能力位。

建议至少覆盖：

- Display API
- Audio API
- Input API
- OTA
- Diagnostics
- 日志导出
- 配件识别

## 5. 兼容矩阵字段

每个公开发布版本至少记录：

- 协议版本
- SDK 版本
- 固件版本
- 硬件版本
- 已验证的手机系统版本
- 已知限制

## 6. 当前状态

协议仍处于初始化阶段，尚未分配正式版本号，也没有对外承诺的能力位或兼容矩阵。首个开发版本将在设备联调后发布。
